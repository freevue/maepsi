# bab-lint

프로젝트가 문서로 채택한 디자인 규칙을 실제 UI와 대조합니다. 규칙이 없는 곳에 임의의 취향을 필수 기준으로 적용하지 않습니다.

## 검사 범위

1. 요청한 화면이나 경로를 우선합니다. 범위가 없으면 변경된 UI 파일과 관련 화면을 고릅니다. 검사한 파일과 화면을 보고합니다. UI 대상이 없으면 `검사 대상 없음`으로 보고합니다.
2. 해당 경로의 `DESIGN.md`, 연결된 디자인 문서와 로컬 규칙을 읽습니다. 토큰이나 공용 컴포넌트의 정의가 있다면 함께 확인합니다. 문서가 충돌하고 우선순위가 없으면 그 규칙의 판정을 보류합니다.
3. 적용할 디자인 규칙이 없으면 `검사 대상 없음`으로 보고합니다. 이 상태를 `통과`로 표시하지 않습니다.

## 대조 방법

- 채택된 규칙에서 색, 글꼴, 간격, 컴포넌트, 상태, 반응형 동작 중 현재 화면에 적용되는 항목을 고릅니다. 해당 코드와 설정을 읽고 규칙의 위치와 실제 값을 대조합니다.
- 프로젝트에 검사 명령이 있으면 쓰기나 자동 수정이 없는 모드로 실행합니다. 실행한 명령과 결과를 기록합니다. 설치, 포매팅, 코드 수정은 하지 않습니다.
- 화면을 실행하거나 스크린샷을 볼 수 있으면 적용되는 상태와 화면 크기에서 확인합니다. 기준 화면이 있다면 같은 조건의 결과와 비교합니다. 코드 검사만으로 픽셀 배치나 실제 조작을 확인했다고 말하지 않습니다.
- 접근성 규칙이 문서나 프로젝트 설정에 있으면 그 규칙을 검사합니다. 기본적인 사용성 문제를 발견하면 채택 규칙 위반과 구분해 `권고`로 보고합니다.

## 결과

먼저 `위반 있음`, `확인한 범위에서 통과`, `검사 대상 없음` 중 하나를 말합니다. 각 위반에 규칙의 문서 위치, 구현 위치, 실제 차이와 영향, 필요한 수정을 적습니다. 같은 규칙의 반복 위반은 개수와 대표 위치를 적습니다.

코드·설정 검사, 실행한 자동 검사, 실제 화면 확인을 각각 구분합니다. 열지 못한 화면, 확인하지 못한 상태나 화면 크기, 실행하지 못한 검사는 `미검증`으로 기록합니다. 검사 중 발견한 비밀값과 개인정보는 원문으로 옮기지 않습니다.
