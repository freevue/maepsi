# bab-lint lint

대상 프로젝트가 정한 디자인 문서를 검사합니다. 이 플러그인의 예시나 에이전트의 취향을 프로젝트 규칙으로 취급하지 않습니다.

## 검사 대상

1. 대상 저장소의 에이전트 지침과 문서 규칙을 읽습니다. 요청한 문서와 UI 범위를 우선합니다. 범위가 없으면 프로젝트의 `DESIGN.md` 또는 같은 역할의 진입 문서에서 연결된 디자인 시스템 문서를 찾습니다.
2. 문서가 없으면 `문서 없음`으로 보고하고 `bab-lint:document`로 정리할 자료를 안내합니다. 이 상태를 통과로 표시하지 않습니다.
3. 디자인 원본, 문서, 토큰·컴포넌트 설정, 구현 중 실제로 확인한 자료를 기록합니다. 서로 다른 문서가 충돌하고 우선순위가 없으면 판정을 보류합니다.

## 문서 검사

- 진입 문서에서 관련 토큰·컴포넌트·화면 문서와 사용 가이드를 정확히 찾을 수 있는지 봅니다. 깨진 링크, 같은 규칙의 중복 정본, 정의되지 않은 토큰이나 컴포넌트 참조를 찾습니다.
- 사용자 결정으로 확정된 값과 기존 구현에서 관찰한 값, 아직 결정되지 않은 값을 구분하는지 봅니다. 출처가 없는 관찰값을 확정 규칙으로 판정하지 않습니다.
- 문서가 약속한 범위에서 정확한 값과 단위, 공용 컴포넌트의 공개 props·속성의 타입·기본값·용도·시각적 효과, 변형·상태·상호작용, 화면 크기별 동작을 재현할 수 있는지 확인합니다. 빠진 항목은 해당 문서와 근거를 들어 보고합니다.
- 사용 가이드가 컴포넌트와 토큰을 화면에서 조합하는 기준, 좋은 예와 피할 예, 적용 범위를 설명하는지 봅니다. 주관적 인상만 있고 판정 근거가 없으면 보완할 질문으로 보고합니다.
- 디자인 원본에 접근할 수 있으면 문서의 값과 구성을 대조합니다. 원본을 볼 수 없다면 원본 일치 여부를 `미검증`으로 남깁니다.

## 구현 검사

- 해당 UI가 있으면 확정된 문서 규칙과 토큰, 컴포넌트 선택·사용, 화면의 위계·간격·상태·반응형 동작을 코드·설정에 대조합니다. 새 공용 컴포넌트의 문서와 사용 가이드가 있는지도 봅니다. 관찰 또는 미결정 항목은 위반 기준으로 쓰지 않습니다.
- 프로젝트의 기존 검사 명령은 쓰기나 자동 수정이 없는 모드로만 실행합니다. 패키지 설치, 포매팅, 코드·문서 수정은 하지 않습니다.
- 화면을 실행하거나 스크린샷을 볼 수 있으면 같은 상태와 화면 크기에서 사용 가이드의 좋은 예·피할 예와 비교합니다. 코드 검사만으로 실제 배치나 조작을 확인했다고 말하지 않습니다. 가이드가 없는 미적 인상은 위반 대신 제안으로 분리합니다.

## 결과

문서와 구현을 각각 `불일치`, `확인한 범위에서 일치`, `문서 없음`, `대상 없음`, `미검증` 중 해당 상태로 보고합니다. 각 문제에 문서 규칙, 디자인 원본 또는 구현의 위치, 실제 차이와 필요한 조치를 적습니다. 같은 문제는 대표 사례와 총개수로 묶습니다.

실행한 명령, 확인한 화면·상태·화면 크기와 확인하지 못한 범위를 밝힙니다. 비밀값과 개인정보는 원문으로 기록하지 않습니다.
