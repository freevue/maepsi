# bab-lint setup

대상 프로젝트의 디자인 기준을 처음 문서화합니다. 플러그인의 취향이나 외부 사례를 프로젝트 규칙으로 복사하지 않습니다.

1. 대상 저장소의 에이전트 지침과 기존 디자인 문서 구조를 읽습니다. [초기 조사와 질문 기준](references/initial-review.md)에 따라 실제 화면, 스타일·토큰 선언과 공용 UI 컴포넌트를 조사합니다. 화면을 실행할 수 없으면 코드에서 관찰한 값과 시각적으로 확인한 값을 구분합니다.
2. 현재 디자인의 색상과 시각 요소를 역할별로 요약하고, 대표 화면과 함께 사용자에게 보여줍니다. 유지할 것, 바꿀 것, 예외를 작은 묶음으로 묻습니다. 답을 기다리는 동안 확인 가능한 자료와 문서 초안을 정리합니다.
3. 사용자 결정 또는 충돌 없는 기존 정본은 `확정`, 코드·화면에서만 찾은 값은 `관찰`, 근거가 없거나 충돌하는 값은 `미결정`으로 기록합니다. 외부 사례는 선택 후보로만 제시합니다.
4. 기존 진입 문서가 없으면 대상 프로젝트에 `DESIGN.md`를 만듭니다. 디자인 시스템을 담당하는 공용 컴포넌트마다 공개 props와 속성의 타입·기본값·용도·시각적 효과, 변형·상태·상호작용을 문서화합니다. 컴포넌트 구현과 문서의 정확한 연결을 남깁니다.
5. 토큰과 컴포넌트를 화면에서 사용하는 기준을 사용 가이드로 정리합니다. 화면의 위계·간격·콘텐츠·상태·반응형·움직임을 실제 사례와 함께 기록합니다. 사용자가 채택하지 않은 후보는 강제 규칙으로 넣지 않습니다.
6. [lint 검사 기준](../lint/SKILL.md)으로 문서의 링크·정본·누락과 확인 가능한 구현을 검사합니다. 실제 화면을 확인했다면 화면 크기와 상태를 적습니다. 질문이 남거나 공용 컴포넌트 문서가 빠졌다면 setup을 완료로 보고하지 않습니다.

마지막에 생성·수정한 문서, 조사한 화면과 컴포넌트, 확정·관찰·미결정 사항, 사용자에게 남은 결정과 미검증 범위를 보고합니다. 코드 수정이나 임의의 디자인 변경은 별도 요청이 있을 때만 합니다.
