# bab-lint document

사용자의 디자인을 대상 프로젝트의 문서로 옮깁니다. 플러그인에 내장된 디자인이나 고정 템플릿을 복사하지 않습니다.

## 근거 모으기

1. 대상 저장소의 에이전트 지침과 문서 규칙을 읽습니다. 사용자가 준 화면, 이미지, 디자인 파일, 설명과 기존 문서·토큰·컴포넌트를 확인합니다. 열 수 없는 원본은 이름과 이유를 기록합니다.
2. 디자인 값마다 근거를 구분합니다. 사용자가 결정했거나 충돌 없이 채택된 문서의 값은 `확정`, 코드와 화면에서만 찾은 값은 `관찰`, 자료가 부족하거나 출처가 충돌하는 값은 `미결정`입니다. 관찰값을 승인 없이 확정 규칙으로 올리지 않습니다.
3. 기존 문서 구조가 있으면 유지합니다. 진입 문서가 없다면 대상 프로젝트에 `DESIGN.md`를 만들고 상세 문서를 연결합니다. 문서 경로와 분류는 프로젝트 구조에 맞춥니다.

## 문서 작성

- 진입 문서에는 적용 범위, 디자인 원본, 결정 상태와 토큰·컴포넌트·화면 문서의 정확한 링크를 둡니다. 같은 규칙의 정본을 여러 곳에 복사하지 않습니다.
- 디자인 시스템 문서에는 해당되는 토큰의 이름·값·단위·사용처를 적습니다. 컴포넌트에는 이름과 구현 경로, 변형, 상태, 상호작용, 반응형 동작과 사용하는 토큰을 적습니다.
- 화면 문서에는 구성 컴포넌트, 상태 변화와 화면 크기별 동작을 적습니다. 코드에서만 확인한 값은 `관찰`, 어느 자료에도 없는 값은 `미결정`으로 남깁니다.
- 문서에 출처와 판단 근거를 남깁니다. 이미지나 디자인 파일을 복사할 권한이 불명확하면 원본 경로와 필요한 설명만 적습니다. 코드 수정은 별도 요청이 있을 때만 합니다.

## 작성 후 확인

작성한 문서와 연결된 자료에 [lint 검사 기준](../lint/SKILL.md)을 적용합니다. 문서 링크와 참조, 출처, 값의 충돌을 확인합니다. 구현과 실제 화면까지 확인했다면 그 범위를 따로 기록합니다.

마지막에 만든·고친 문서, 확인한 원본, 확정·관찰·미결정 항목과 미검증 범위를 보고합니다. 사용자 결정이 필요한 항목은 질문으로 모으되, 나머지 문서 작업은 끝냅니다.
